# Python OOP & Exception 확인 문제 (통합) — 정답 및 해설

## Ⅰ. 객관식

**1. 정답: d** ●쉬움 · ①
- **해설:** 클래스는 `class 클래스이름:` 형식으로 정의합니다. `define`이나 `def class` 같은 문법은 파이썬에 없습니다.
- **출제 근거:** 클래스 정의의 기본 문법을 구분할 수 있는지 확인합니다.

**2. 정답: b** ●쉬움 · ①
- **해설:** OOP는 데이터(속성)와 그 데이터를 처리하는 기능(메서드)을 하나의 객체로 묶어 관리하는 방식입니다. a)는 절차 지향에 가까운 설명입니다.
- **출제 근거:** 절차 지향과 대비되는 객체 지향의 핵심 개념(데이터+기능의 결합)을 이해했는지 확인합니다.

**3. 정답: c** ●쉬움 · ①
- **해설:** 하나의 클래스(설계도)로부터 여러 개의 인스턴스를 만들 수 있습니다. "하나만 만들 수 있다"는 설명이 틀렸습니다.
- **출제 근거:** 클래스-인스턴스 관계(1:N)를 정확히 이해했는지 확인합니다.

**4. 정답: b** ●쉬움 · ①
- **해설:** 인스턴스 메서드는 반드시 첫 번째 매개변수로 인스턴스 자신(`self`)을 받습니다.
- **출제 근거:** 인스턴스 메서드 정의 규칙(self)을 알고 있는지 확인합니다.

**5. 정답: d** ◐보통 · ①
- **해설:** 클래스 변수는 모든 인스턴스가 공유하므로 인스턴스마다 개별 값을 갖지 않습니다. 개별 값을 갖는 것은 인스턴스 변수입니다.
- **출제 근거:** 클래스 변수와 인스턴스 변수의 차이를 구분할 수 있는지 확인합니다.

**6. 정답: a** ◐보통 · ①
- **해설:** 스태틱 메서드는 `self`나 `cls`를 받지 않으며, 클래스·인스턴스와 무관하게 객체 없이도 호출할 수 있습니다.
- **출제 근거:** 스태틱 메서드의 독립성(상태에 의존하지 않음)을 이해했는지 확인합니다.

**7. 정답: a** ◐보통 · ①
- **해설:** 인스턴스 메서드는 `self`, 클래스 메서드는 `cls`를 자동으로 받고, 스태틱 메서드는 자동 전달 인자가 없습니다.
- **출제 근거:** 세 가지 메서드를 첫 번째 인자 기준으로 명확히 구분할 수 있는지 확인합니다.

**8. 정답: b** ◆어려움 · ①
- **해설:** 속성 접근은 인스턴스 → 클래스 순으로 탐색됩니다. `p1`은 인스턴스 변수가 없어 클래스 변수 `'unknown'`을 출력하고, `p2`는 인스턴스 변수 `'Kim'`을 갖게 되어 `'Kim'`을 출력합니다. (클래스 변수 자체가 바뀐 것은 아님)
- **출제 근거:** 이름 공간(namespace)의 탐색 순서와 "인스턴스 변수가 클래스 변수보다 우선한다"는 원리를 코드로 적용할 수 있는지 확인합니다.

**9. 정답: a** ●쉬움 · ②
- **해설:** 상속은 부모 클래스의 속성과 메서드를 자식 클래스가 물려받는 것입니다. b)는 오버로딩, c)는 예외 처리, d)는 디버깅 설명입니다.
- **출제 근거:** 상속의 정의를 유사 개념과 혼동하지 않는지 확인합니다.

**10. 정답: b** ●쉬움 · ②
- **해설:** 자식 클래스는 `class 자식(부모):` 형태로 괄호 안에 부모 클래스 이름을 함께 선언해야 합니다.
- **출제 근거:** 상속 선언 문법을 코드로 쓸 수 있는지 확인합니다.

**11. 정답: b** ●쉬움 · ②
- **해설:** 오버라이딩은 부모 메서드를 같은 이름·같은 파라미터 구조로 재정의하는 것입니다. a)는 파이썬이 지원하지 않는 오버로딩, d)는 다중 상속 설명입니다.
- **출제 근거:** 오버라이딩과 오버로딩을 구분할 수 있는지 확인합니다.

**12. 정답: b** ◐보통 · ②
- **해설:** `Cat`이 `sound`를 오버라이딩했으므로 자식의 메서드가 실행되어 `야옹`이 출력됩니다. 부모 메서드는 실행되지 않습니다.
- **출제 근거:** 오버라이딩 시 "부모 대신 자식 메서드가 실행된다"는 동작 원리를 코드 실행 결과로 검증합니다.

**13. 정답: b** ●쉬움 · ②
- **해설:** `super()`는 부모 클래스 이름을 직접 적지 않고 MRO에 따라 부모 메서드를 호출하게 해 주어 유지보수성을 높입니다.
- **출제 근거:** `super()`의 핵심 목적을 이해했는지 확인합니다.

**14. 정답: b** ◆어려움 · ②
- **해설:** `class Child(Dad, Mom)`의 MRO는 `Child → Dad → Mom → Person` 순입니다. `gene`을 찾을 때 왼쪽 부모인 `Dad`를 먼저 탐색하므로 `'XY'`가 출력됩니다.
- **출제 근거:** 다중 상속 시 중복 속성이 상속 순서(왼쪽 우선)에 의해 결정된다는 원리를 코드로 적용할 수 있는지 확인합니다.

**15. 정답: c** ●쉬움 · ②
- **해설:** 딕셔너리에 존재하지 않는 키(`'age'`)를 조회하면 `KeyError`가 발생합니다. (리스트의 잘못된 인덱스는 `IndexError`)
- **출제 근거:** 자료형에 따라 발생하는 예외가 다르다는 점(딕셔너리 → KeyError)을 구분할 수 있는지 확인합니다.

## Ⅱ. 주관식

**16. 정답: `__init__`** ●쉬움 · ①
- **해설:** 생성자 메서드는 `__init__`이라는 이름으로 정의하며, 인스턴스 생성 시 자동 호출되어 인스턴스 변수를 초기화합니다.
- **출제 근거:** 생성자 메서드의 이름을 정확히 인출할 수 있는지 확인합니다.

**17. 정답: 14** ◐보통 · ①
- **해설:** `double`은 스태틱 메서드이므로 인스턴스 없이 `클래스명.메서드()`로 호출할 수 있고, `7 * 2 = 14`를 반환·출력합니다.
- **출제 근거:** 스태틱 메서드를 인스턴스 생성 없이 호출하는 방식과 반환값을 이해했는지 확인합니다.

**18. 정답: `super()`** ●쉬움 · ②
- **해설:** `super().__init__(name, age)`로 부모 생성자를 호출해 공통 속성을 초기화한 뒤, 자식 고유 속성(`student_id`)을 추가합니다.
- **출제 근거:** 단일 상속에서 `super()`로 부모 생성자를 호출하는 사용 패턴을 알고 있는지 확인합니다.

**19. 정답: `IndexError`** ◐보통 · ②
- **해설:** 리스트의 유효한 인덱스는 0~2인데 `nums[5]`는 범위를 벗어나 `IndexError: list index out of range`가 발생합니다.
- **출제 근거:** 시퀀스 인덱스 초과 시 발생하는 예외 이름을 정확히 쓸 수 있는지 확인합니다.

**20. 정답: (1) EAFP  (2) LBYL** ◐보통 · ②
- **해설:** EAFP = "Easier to Ask for Forgiveness than Permission"(먼저 실행 후 예외 처리), LBYL = "Look Before You Leap"(먼저 검사 후 실행).
- **출제 근거:** 두 예외 처리 스타일의 약어와 개념을 짝지어 기억하는지 확인합니다.

## Ⅲ. 서술형

**21.** ◆어려움 · ①
- **모범 답안(예시):**
  - **인스턴스 메서드**: 첫 번째 인자로 **`self`**(인스턴스 자신)를 받으며, 개별 인스턴스의 상태(속성)를 조회·변경하는 데 사용한다.
  - **클래스 메서드**: `@classmethod`로 정의하고 첫 번째 인자로 **`cls`**(클래스 자신)를 받으며, 클래스 변수를 조작하는 등 클래스 레벨의 동작에 사용한다.
  - **스태틱 메서드**: `@staticmethod`로 정의하고 **자동 전달 인자가 없으며(self·cls 모두 없음)**, 클래스·인스턴스 상태와 무관한 독립적인 기능(유틸리티)에 사용한다.
- **채점 포인트:** 세 메서드 각각의 첫 인자(self / cls / 없음) + 용도가 올바르게 대응되면 만점.
- **출제 근거:** 세 가지 메서드를 단순 나열이 아니라 "무엇을 대상으로 동작하는가"를 기준으로 구분해 설명할 수 있는지 확인합니다.

**22.** ◆어려움 · ②
- **모범 답안(예시):** 내장 예외 클래스는 **상속 계층 구조**를 가지며, `Exception`은 대부분 예외의 상위(부모) 클래스입니다. `except` 절은 위에서부터 차례로 검사되는데, 범용 예외인 `except Exception`을 먼저 두면 그 하위에 속하는 `ZeroDivisionError` 같은 예외까지 **모두 먼저 가로채** 버립니다. 그 결과 아래에 있는 구체적 예외 전용 처리 코드에는 **도달할 수 없게** 됩니다. 따라서 가장 구체적인 예외를 먼저 처리하고 범용 예외를 마지막에 배치해야 각 상황에 맞는 처리가 가능합니다.
- **채점 포인트:** (1) 예외의 상속 계층 언급, (2) 상위 예외가 하위 예외를 먼저 가로챈다는 점, (3) 하위 전용 블록에 도달 불가라는 결과 — 세 요소 포함 시 만점.
- **출제 근거:** 규칙 암기를 넘어, 그 규칙이 성립하는 원리(상속 계층 + 순차 검사)를 설명할 수 있는지 확인합니다.
